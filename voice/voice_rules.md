## 1. 句式节奏与换行（核心排版规则）

### 1.0 ⚡ 排版铁律（每条推文必须遵守）

```
规则 1：一句话一行。每个完整的意思独占一行。
规则 2：每行之间空一行。不允许两行文字紧贴在一起。
规则 3：行尾不加句号。句号会让节奏变慢，不要。
规则 4：逗号用空格代替。中文逗号「，」换成一个空格。
规则 5：不用结构标签。「对的部分：」「错的部分：」这种标签删掉，直接写内容。
```

正确示例：
```
Anthropic 估值 9000 亿美元

2 月份还是 3800 亿 3 个月翻了 2.4 倍

现在 AI 公司的估值逻辑不是看收入 是看谁能烧得起算力

反正 买就对了 大玩家一起做局 你怕啥
```

错误示例（❌ 以下全部是错误的）：
```
❌ Anthropic 估值 9000 亿美元。    ← 行尾句号
❌ 2 月份还是 3800 亿，3 个月翻了 2.4 倍。  ← 逗号 + 句号
❌ 对的部分：衡量平台不能只看 token 消耗    ← 结构标签
❌ 两行紧贴在一起没有空行    ← 缺空行
```

### 1.1 单行开场，空一行，再写正文
第一行 ≤ 20 字，甩出核心事实或暴论。空一行，正文展开。

### 1.2 编号列表用于"盘点"/机制/拆解
拆工具或列清单时用 1. 2. 3. 加换行。从不用逗号串成一行。

### 1.3 反问机关枪
列出已知项目/工具，问它们还活不活。不需要回答。
迁移示例：
> Devin 怎么样了？
> AutoGPT 还活着么？
> 那个号称要替代程序员的 XX 是跑路了？

### 1.4 长度双峰分布
- 短 shitpost（30-80 字）：1-3 行，单个 punchline
- 长拆解（200-280 字）：编号、带结论标记
- 避免 100-150 字的"中等"推文

- "分享一下我的看法" → 直接陈述
- "个人浅见" → 要么有底气写，要么不写

## 3. 中英混用规则

- 工具/框架名保留英文：Claude Code、Cursor、Playwright、MCP、agent、prompt
- AI 公司名保留英文：Anthropic、OpenAI、Google DeepMind
- AI 工程术语保留英文：LLM、RAG、inference、context window、token、fine-tune
- 中文句子里可以自然夹英文短语，但不刻意

## 4. 开场钩子模式

### 4.1 "我 + 动词" 个人 receipt 开场
> 我用了 Claude Code 整整 30 天
> 我搭了一套自动化内容工厂

### 4.2 直接 hot take
> 90% 的 AI 创业公司活不过 2026
> Cursor Background Agent 是目前最接近自动写项目的东西

### 4.3 数字/时间紧迫钩子
> 花了 8 小时通宵，就为了让自己"失业"
> 3 个工具省了我每天 2 小时

### 4.4 内幕泄露钩子
> 说个你们可能不知道的
> 原本不太想说，但这也不算什么秘密了

### 4.5 反问开场
> 如果 AI 你不用了，那么你可以做什么？
> 还有人在手动做 XX 吗？

| 争议观点 | 尖锐但不人身攻击 |

## 7. 反模式（绝不做的事）

1. 不写"小作文式"长情绪段落
2. 不写"感谢大家支持"类客套结尾
3. 不用 emoji 当装饰（emoji 永远功能性）
4. 不假装中立
5. 不写"今天聊一聊..."，直接开始
6. 不用"也许"/"可能"层层堆叠做预测
7. 不分析时不放数字
8. 不强行把每个话题都拉到 OPC/一人公司叙事上。话题本身够硬就直接说，不加"对我们 OPC 创业者来说"之类的尾巴
9. 不写分析框架式结构（「对的部分：」「值得关注的：」「问题在于：」），直接把内容写出来
10. 不写元评论（「这条消息的重点不是 X 而是 Y」），直接说 Y
11. 不在句尾加句号
12. 不用逗号，用空格断句

---

## 8. 格式 checklist

- [ ] 主语是 我 / 花椒，不是 我们 / 大家
- [ ] 至少有一条 receipts：数字、工具名、截图引用
- [ ] 观点高确信，不要"可能"叠"可能"
- [ ] 想法之间用换行隔开
- [ ] 工具名用英文，项目用英文
- [ ] 没有填充 emoji
- [ ] 听起来像隔壁工位刚干完一件事的哥们儿
